# ConfFirst

Эмулятор командной оболочки UNIX-подобной ОС.
Практическая работа по дисциплине «Конфигурационное управление».
Вариант №11: GUI на Python (tkinter), VFS из CSV-файла.

## Общее описание

Приложение эмулирует командную оболочку UNIX-подобной ОС:

- графический интерфейс (tkinter) с заголовком окна, содержащим имя VFS;
- парсер командной строки (разделение по пробелам);
- виртуальная файловая система (VFS) в памяти, загружаемая из CSV;
- поддержка стартовых скриптов и параметров командной строки;
- команды: `ls`, `cd`, `uname`, `head`, `history`, `mkdir`,
  `vfs-init`, `cat`, `grep`, `exit`.

Вся логика (VFS, команды, оболочка) реализована на Python; GUI вызывает
оболочку напрямую, без отдельного процесса и протокола.

## Требования

- Python 3 с tkinter (модуль входит в стандартную поставку Python).
  Нужен интерпретатор с Tk версии 8.6 и новее: на новой macOS сборки
  с Tk 8.5 (например, системный Python) не запускают окно. `run.sh`
  сам подбирает подходящий интерпретатор из установленных.

## Запуск

```sh
./run.sh --vfs vfs/medium.csv --script scripts/startup_stage1.txt
```

Параметры командной строки:

- `--vfs` — путь к физическому расположению VFS (CSV-файл);
- `--script` — путь к стартовому скрипту с командами эмулятора.

При запуске эмулятор выводит значения всех параметров в отладочный вывод.
Стартовый скрипт выполняется построчно, при этом ввод и вывод печатаются
в окно (имитация диалога), а выполнение останавливается на первой ошибке.

Скрипты в `scripts/` запускают эмулятор с разными наборами параметров:

- `test_no_args.sh` — без параметров;
- `test_vfs_only.sh` — только `--vfs`;
- `test_script_only.sh` — только `--script`;
- `test_full.sh` — оба параметра;
- `test_error_stop.sh` — остановка скрипта на первой ошибке.

## VFS

Источником VFS является CSV-файл с колонками `type,path,owner,content`:

- `type` — `d` для папки или `f` для файла;
- `path` — полный путь элемента (вложенность задаётся самим путём);
- `owner` — владелец элемента;
- `content` — содержимое файла в кодировке base64 (для папок пусто).

VFS целиком загружается в память, исходный файл не распаковывается и не
изменяется. При ошибке загрузки (файл не найден, неверный формат) эмулятор
сообщает об этом в окне. Команда `vfs-init` заменяет текущую VFS на VFS по
умолчанию и очищает физическое представление (файл, заданный через `--vfs`).

Тестовые VFS в `vfs/`: `minimal.csv` (корень и один файл), `medium.csv`
(несколько файлов и папок), `deep.csv` (вложенность от трёх уровней),
`broken.csv` (неверный формат для проверки ошибки загрузки).

Скрипты реальной ОС для проверки VFS:

- `test_vfs_minimal.sh`, `test_vfs_medium.sh`, `test_vfs_deep.sh` — запуск с
  соответствующей VFS и стартовым скриптом;
- `test_vfs_init.sh` — проверка очистки физической VFS командой `vfs-init`;
- `test_vfs_invalid.sh`, `test_vfs_missing.sh` — обработка ошибок загрузки.
